# 정치 뉴스 블로그·영상 자동화

매일 아침 정치 뉴스를 알아서 모아서, **네이버 블로그에 올릴 글**과 **영상 대본**을 만들어 둡니다.
사장님은 아침에 링크 하나만 열면 됩니다.

> 이 프로젝트는 부동산 브리핑(`estate-news`)을 2026-09-08 에 복사해 정치 뉴스용으로 고친 것입니다.
> **어느 정당·인물의 편도 들지 않는 것**이 첫째 원칙이고, 여론조사를 인용할 때는 조사 개요를 함께 밝힙니다.

## 처음 한 번만 하는 설정

컴퓨터에 뭘 설치할 필요 없습니다. **인터넷 브라우저만 있으면 됩니다.**
아래 4단계를 한 번만 해두면 그다음부터는 알아서 돌아갑니다.

### 1단계 · 열쇠 만들기 (AI 사용료 계정)

글을 써주는 건 AI(Claude)입니다. 그걸 쓰려면 "열쇠"가 하나 필요합니다.

1. [console.anthropic.com](https://console.anthropic.com) 에 가입합니다
2. 결제 수단을 등록합니다 (하루 약 590원, 한 달 약 1만 8천 원. 자세한 건 아래 [비용](#비용))
3. **API Keys** 메뉴에서 **Create Key** 를 누릅니다
4. 나온 글자(`sk-ant-...` 로 시작)를 **복사**합니다 — 이 화면을 닫으면 다시 못 봅니다

### 2단계 · 열쇠를 저장소에 넣기

1. 이 저장소(깃허브 페이지)에서 위쪽 **Settings** 를 누릅니다
2. 왼쪽 목록에서 **Secrets and variables** → **Actions** 를 누릅니다
3. 초록색 **New repository secret** 버튼을 누릅니다
4. 이름(Name) 칸에 정확히 이렇게 적습니다: `ANTHROPIC_API_KEY`
5. 값(Secret) 칸에 1단계에서 복사한 열쇠를 붙여넣습니다
6. **Add secret** 을 누릅니다

> 이 열쇠는 사장님만 볼 수 있게 저장됩니다. 다른 사람에게 보이지 않습니다.

### 3단계 · 결과를 저장할 수 있게 허락하기

1. **Settings** → 왼쪽에서 **Actions** → **General** 을 누릅니다
2. 화면을 아래로 끝까지 내립니다
3. **Workflow permissions** 에서 **Read and write permissions** 를 고릅니다
4. **Save** 를 누릅니다

### 4단계 · 첫 글 만들기

1. 위쪽 **Actions** 탭을 누릅니다
2. 왼쪽 목록에서 **정치 데일리 브리핑** 을 고릅니다
3. 오른쪽 **Run workflow** 버튼을 누릅니다 (3~5분 걸립니다)
4. 초록색 체크 표시가 뜨면 잠시 뒤 **사이트 배포** 가 이어서 자동으로 돕니다

끝나면 이 주소가 열립니다. **휴대폰에 즐겨찾기 해두세요.**

**https://www.rokiz.net/politics-news/**

> 이 저장소에는 개인 도메인 `www.rokiz.net` 이 연결돼 있어 이 주소로 열립니다.
> 깃허브 기본 주소인 `https://rokieyez.github.io/politics-news/` 로도 똑같이 열립니다.
>
> 매일 볼 링크는 따로 설정할 게 없습니다. 워크플로가 알아서 만들어 줍니다.
> 정확한 주소는 **Actions → 사이트 배포** 실행 결과 화면에도 매번 표시됩니다.

이제부터 **매일 오전 7시**에 알아서 새 글이 준비됩니다.

### 네이버 블로그에 올리는 법 (30초)

**네이버 블로그 글** 을 누르면 위에 초록색 버튼 4개가 있습니다.

1. **글쓰기 열기** → 네이버 블로그 글쓰기 화면이 새 창으로 열립니다
2. **제목 복사** → 네이버의 제목 칸에 붙여넣기 (휴대폰은 길게 눌러서 "붙여넣기")
3. **본문 복사** → 본문 칸에 붙여넣기. 맨 위에 **오늘의 숫자** 표(핵심 수치 3개)가 붙고, 그 수치가 본문에 처음 나온 자리는 굵은 형광펜, 세 번 이상 되풀이된 수치는 첫 자리 형광펜·이후 밑줄입니다. 필요 없으면 에디터에서 지우세요.
   - 소제목, 표, 굵은 글씨가 **그대로 살아납니다**
4. 점선 상자(📷 이미지)가 보이면 그 자리에 사진을 넣고 상자는 지웁니다
   - **초록 상자**는 그림이 이미 만들어진 자리입니다. 상자에 적힌 파일명
     (예: `img-1-district-map.png`)을 같은 폴더에서 찾아 올리면 됩니다. 휴대폰이면
     사이트의 **그림·썸네일** 페이지에서 길게 눌러 저장하세요.
   - 점선 상자는 사진 자리입니다. 직접 찾으신 사진을 넣으세요.
5. 맨 아래 `#해시태그` 는 **그대로 두세요** — 네이버가 알아서 태그로 등록합니다
6. 발행

화면 아래쪽 노란 안내문과 초록색 바는 복사에 **안 섞입니다.** 신경 안 쓰셔도 됩니다.

## 아침에 알림 받기 (선택)

알림에는 헤드라인과 함께 그달 신고 매매 건수, 이번 달 신고가 한 건이 들어갑니다.
폰만 보고도 오늘 글을 올릴지 판단하실 수 있습니다.

텔레그램 봇을 하나 만들어 두면 매일 7시 실행이 끝날 때 헤드라인과 사이트 링크가
휴대폰으로 옵니다. 실패해도 알려 줍니다. 5분이면 됩니다.

1. 텔레그램에서 **@BotFather** 를 검색해 대화를 열고 `/newbot` 을 보냅니다.
   이름을 두 번 물어보면 아무렇게나 답합니다. 마지막에 **토큰**(숫자:영문 긴 문자열)을 줍니다.
2. 방금 만든 봇을 검색해 대화를 열고 **아무 말이나 한 번** 보냅니다. (이걸 안 하면 봇이 먼저 말을 못 겁니다)
3. 브라우저 주소창에 `https://api.telegram.org/bot<토큰>/getUpdates` 를 엽니다.
   화면에서 `"chat":{"id":` 뒤의 숫자가 **채팅 ID** 입니다.
4. 깃허브 저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**
   - `TELEGRAM_BOT_TOKEN` = 1번 토큰
   - `TELEGRAM_CHAT_ID` = 3번 숫자

컴퓨터에서 직접 돌릴 때도 받으려면 `.env` 에 같은 두 줄을 넣으세요.

## 발행 전에 이것만 보세요 — 점검표

사이트 첫 화면 맨 위에 **발행 전 점검** 카드가 뜹니다. ❌가 있으면 고치고 나서, ⚠️만 있으면
한 번 훑고 발행하면 됩니다. 프로그램이 보는 것: 숫자가 기사에 있는지, 링크가 열리는지,
"무조건 오른다" 같은 금지 표현을 실제로 안 썼는지, 글 분량·태그 수·쇼츠 발화량, 비어 있는 사진 자리.
파일로는 `checklist.md` 입니다.

금지 표현("무조건 오른다" 등)이 든 문장은 프로그램이 **저렴한 모델로 그 문장만 고쳐 쓰고**
점검표에 전후를 남깁니다. 고친 문장이 자연스러운지만 보시면 됩니다.

## 7시 실행이 실패하면

07:25에 한 번 더 자동으로 돕니다. 첫 실행(06:45)이 성공했으면 아무것도 하지 않고 끝납니다.

둘 다 안 돌았다면(깃허브가 예약을 빠뜨리는 날이 드물게 있습니다) 깃허브 **Actions** 탭 → **정치 데일리 브리핑** → **Run workflow** 를 누르면 5분 안에 만들어집니다.
(둘 다 실패하면 텔레그램 실패 알림이 두 번 옵니다. **이틀 이상 연속 실패**면 알림 문구가 바뀌고
운영 현황 맨 위에 빨간 띠가 뜹니다 — 그때는 API 키·한도와 피드를 확인하세요.)

## 한 달에 얼마까지만

`config/settings.yaml` 의 `llm.monthly_budget_usd` 에 달러 금액을 넣으면, 그달 누적이
80%를 넘을 때 저렴한 모델로 바뀌고, 다 쓰면 그날 요약을 건너뜁니다(수집은 계속). 0이면 제한 없음.

## 숫자가 맞는지 프로그램이 한 번 더 봅니다

`brief.md` 맨 아래 **숫자 검산** 절에, 브리핑의 각 수치가 기사 제목·본문에 실제로 있는지
대조한 결과가 나옵니다. 확인된 수치는 **원문 링크와 그 문장**이 같이 적혀 클릭 한 번으로 대조됩니다. **미확인**으로 표시된 값은 발행 전에 원문에서 직접 찾아보세요.
AI가 잘못 읽었거나, 기사에는 다른 단위로 적혀 있을 수 있습니다.

## 어떤 제목이 잘 먹히는지 기록하기 (선택)

매일 제목 후보가 5개씩 나오는데, 실제로 어떤 걸 썼고 조회수가 얼마였는지 적어 두면
몇 주 뒤 유형별(질문형·수치형·비교형·서술형) 평균이 나옵니다.

깃허브 → **Actions** → **제목 기록** → **Run workflow** 에서 날짜·어디(blog/longform/shorts)·
고른 번호·조회수를 넣고 실행하면 됩니다. 결과는 사이트의 **운영 현황** 과 `output/INDEX.md` 에 쌓입니다.

## 글이 짧아졌습니다

이슈 다섯 개를 다 설명하면 3천 자가 넘어 아무도 끝까지 읽지 않습니다. 그래서 이렇게 바꿨습니다.

- **메인 이슈 하나만** 깊게 쓰고, 나머지는 **그 밖의 오늘 소식**에 한 줄씩
- 분량 1,200~2,000자 (이전 1,800~3,500자)
- 어려운 말은 글 앞 **낯선 말 풀이** 상자에 한 줄씩 (종부세, LTV 같은 말 40개를 사람이 미리 적어 둔 사전)
- 글 끝에 **그래서 나는?** — 무주택자·1주택자처럼 읽는 사람 유형별로 한 줄

점검표가 이 구조를 지켰는지, 「그래서 나는?」이 비었는지도 확인합니다.

## 첨부파일 한 번에 받기

사이트 첫 화면과 **그림·썸네일** 페이지에 내려받기 버튼이 둘 있습니다 — **블로그 첨부파일**(그림·자막·컷 리스트)과 **카드뉴스**(유튜브 게시물용 정사각 카드)입니다. 가는 곳이 달라 봉투를 나눴습니다.
그림·썸네일·자막(SRT)·컷 리스트(CSV)가 zip 하나로 묶여 있습니다. 휴대폰에서도 받아집니다.

## 검색으로 들어오게 만드는 장치

글마다 **대표 검색어**를 하나 정합니다. 사람들이 실제로 검색창에 칠 말(예: "종부세 대상 자치구")이고,
제목 앞쪽·첫 문단·소제목에 같은 표기로 들어갑니다. 세 자리 중 빠진 곳이 있으면 점검표가 알려 줍니다.

글 맨 앞에는 **3줄 요약**과 **이 글의 순서**(목차)가 붙고, 끝에는 **질문 한 줄**과
**함께 보면 좋은 지난 글** 링크가 붙습니다. 검색으로 들어온 사람이 바로 판단하고,
한 편 더 보고 가게 하려는 것입니다. 지난 글 링크는 **발행 기록**에 주소를 적어 둔 날만 나옵니다.

점검표에는 **지난 글과 겹치는 문장 비율**도 나옵니다. 매일 같은 문장을 쓰면
검색에서 중복 문서로 취급될 수 있어서, 15%를 넘으면 표현을 바꾸라고 알려 줍니다.

## 발행했다고 표시하기 (선택)

네이버에 글을 올린 뒤 깃허브 → **Actions** → **발행 기록** → **Run workflow** 에 글 주소를 넣으면
사이트 첫 화면에 **발행함** 과 글 링크가 뜹니다. 조회수는 나중에 다시 실행해 채워도 됩니다.

## 이번 주 볼 것

브리핑마다 나오는 '내일 확인할 것'을 모아 사이트 아래 **이번 주 볼 것** 에 쌓아 둡니다.
발표·지표 일정을 한눈에 볼 수 있고, 같은 말은 한 번만 실립니다.

여기에 **정부 발표에 적힌 날짜**가 함께 올라갑니다. 보도자료 원문에서 "10월 24일까지 입법예고",
"12월 1일부터 시행" 같은 앞으로의 일정만 골라 담습니다. 지나간 날짜와 통계표의 숫자는 뺍니다.
날짜를 누르면 그 근거가 된 보도자료로 갑니다.

## 영상 편집용 파일

쇼츠 대본 페이지에서 두 가지를 내려받을 수 있습니다.

- **자막(`script-shorts.srt`)** — 한 줄 16자, 두 줄로 끊어 둡니다. 세로 화면에서 읽기 좋게.
- **컷 리스트(`shorts-cuts.csv`)** — 컷마다 타임코드·자막·화면 지시·쓸 그림 파일명. 엑셀에서 바로 열립니다.

롱폼은 챕터 마커(`longform-chapters.csv`)가 같은 방식으로 나옵니다.

## 정부 정책이 나온 날

새 정책이 나오면 정부 부처가 보도자료를 내려보냅니다. 그 원문을
**정책브리핑**(korea.kr)에서 찾아 **3줄 요약 + 원본 파일**을 함께 올려 둡니다.

- 사이트 첫 화면의 **정부 발표 원문** 을 누르면 됩니다.
- 요약은 부처 문서에 있는 내용만 씁니다. 첨부 PDF 의 글자를 읽어서 줄입니다.
- 원본 파일(주로 PDF)은 링크를 눌러 바로 열 수 있고, 첨부 일괄 내려받기에도 들어갑니다.
- 관련 발표가 없는 날에는 이 항목이 나오지 않습니다. 그날은 정책 발표가 없었다는 뜻입니다.

블로그 글에도 정부 발표가 있는 날이면 원문 링크 상자가 하나 들어갑니다.

같은 정책이 며칠에 걸쳐 여러 번 나오면 **같은 정책의 지난 발표**로 이어 줍니다.
예고 → 확정 → 시행처럼 단계가 나뉘는 정책을 뒤늦게 봐도 앞의 이야기를 따라갈 수 있습니다.

## 정치인 한 사람을 조사하기 (인물 조사)

"이 사람이 누구이고 어떤 길을 걸어왔나" 영상을 만들 때 자료 찾는 일을 대신합니다. **돈이 들지 않는 것이 기본**입니다.

**어디서 누르나** — `https://www.rokiz.net/politics/` 에 이름을 넣고 「조사 시작」. 처음 한 번만 GitHub 열쇠를
넣어야 하는데, 그 페이지의 「열쇠」 칸에 만드는 순서가 적혀 있습니다. 1~4분 뒤 같은 페이지 아래 목록에 나타나고,
「내려받기」를 누르면 파일로 받아집니다. (깃허브 Actions 탭 → 인물 조사 → Run workflow 로 눌러도 같습니다.)

**무엇이 나오나** — 파일 이름은 `이름(생년,정당)_날짜` 로 시작합니다.

| 파일 | 언제 | 무엇 | 비용 |
| --- | --- | --- | --- |
| `…_정리표.md` | 늘 | 기본 정보 · **선거 이력(낙선 포함, 득표율)** · 정당 변천 · 공식 약력 · 발의 법안 수 · 연도별 기사 제목. 프로그램이 표로만 옮긴 것, AI 없음 | 0원 |
| `….md` (자료묶음) | 「자료묶음 파일도 만들기」를 켜면 | 모은 자료 전부 + 지시문. **claude.ai 채팅창에 통째로 붙여 넣으면** 연표·발자취·논란(의혹/해명/상태)·영상 구성안이 나옵니다 | 0원 (구독으로) |
| `…_AI정리.md` | 「AI 정리 글까지」를 켜면 | 붙여 넣는 수고 없이 프로그램이 모델을 불러 같은 정리 글을 만듭니다 | 한 번 약 700원 (첫 실측 $0.50) |

어디서 가져오나 (전부 무료, 인증키 없이 돕니다):

| 자료 | 어디서 | 무엇 |
| --- | --- | --- |
| 공식 기록 [A] | 열린국회정보 | 생년·당선 대수·정당 이력·선거구·공식 약력(학력·경력) |
| 위키백과 [W] | ko.wikipedia.org | 생애·경력·논란·**역대 선거 결과(낙선 포함)**·소속 정당 변천 |
| 발의 법안 [B] | 열린국회정보 | 대수별 발의 건수와 최근 법안 |
| 기사 제목 [N] | 구글뉴스 | 최근 40건 + 정계 입문 때부터 지금까지 4년씩 잘라 시기별 30건 |

주의할 점:

- **위키백과는 누구나 고칠 수 있는 자료**입니다. AI 정리 글은 위키백과에만 있는 사실을 '확인할 것' 에 따로 모아
  둡니다. 그 부분은 영상에 넣기 전에 기사로 한 번 더 확인하세요.
- 기사는 **제목만** 씁니다. 본문을 읽지 않습니다. 정리표의 연도별 기사는 제목에 이름이 든 것 위주로 추립니다.
- AI 정리 글의 논란은 반드시 **의혹 · 당사자 입장 · 현재 상태** 세 칸으로 나옵니다. 해명이 자료에 없으면 점검에 ⚠️ 가
  뜹니다. 유죄 판결이 적힌 항목이 아니면 영상에서 "혐의를 받았다" 로 말하세요.
- 국회의원을 지낸 적 없는 사람은 공식 기록 [A] 가 비고, 위키백과와 기사만으로 정리됩니다.
- **버튼(깃허브 서버)으로 돌리면 열린국회정보 접속이 가끔 끊겨 공식 기록 [A] 와 발의 법안 [B] 가 빠질 수 있습니다.** 그때는
  위키백과 표로 생년·정당·당선을 채우고 정리표 맨 위에 「닿지 못해」 라고 적어 둡니다. 다시 누르면 대개 들어오고, 내 컴퓨터에서 돌리면 늘 들어옵니다.
- 위키백과 글은 CC BY-SA 라 영상 설명란에 「출처: 위키백과 ○○」 한 줄을 적어 주세요.

내 컴퓨터에서는 `python -m rebrief profile "이름"` (동명이인이면 `--birth 1964`, 자료묶음은 `--pack`, AI 정리는 `--llm`).

**열린국회정보 인증키 (선택, 무료)** — 없어도 돌지만 한 번에 5건만 와서 '이번 주 몇 건' 을 세지 못합니다.

3. 나온 키를 저장소 **Settings → Secrets and variables → Actions → New repository secret** 에

## 딱 하나, 자동이 안 되는 것

**네이버 블로그에 글이 저절로 올라가게는 못 합니다.** 이유를 솔직히 말씀드리면:

- 네이버는 "블로그에 글을 쓰는" 기능을 외부에 열어주지 않습니다.
  네이버가 공개한 기능은 **검색**뿐이고, **글쓰기는 없습니다.**
- 시중에 "자동 포스팅 프로그램" 이 팔리긴 합니다. 사람인 척 브라우저를 조작하는 방식인데,
  네이버가 이런 걸 **비정상 이용으로 보고 제재를 강화**하고 있습니다.
  보안업체(안랩)는 이런 프로그램을 아예 **악성 파일로 분류**합니다.
- 잘못하면 **블로그 계정이 정지**되거나 검색에서 밀려납니다.
  몇 년 키운 블로그를 잃을 수 있는 위험을, 30초 아끼자고 감수할 이유는 없다고 봅니다.

그래서 **글을 만드는 데까지는 전부 자동**으로 하고, 마지막 붙여넣기만 남겨뒀습니다.
대신 그 30초가 최대한 편하도록 복사 버튼을 붙여뒀습니다.

> 워드프레스는 자동 발행이 가능합니다. 말씀해 주시면 붙여드리겠습니다.
> (티스토리는 2024년 2월에 외부 글쓰기 기능(Open API)이 종료돼 자동 발행이 안 됩니다.)

## 비용

AI가 하루에 3번 일합니다 (사실 정리 → 블로그 글 → 영상 대본).

**두 번 다 실제로 재 봤습니다.** 고치기 전 9월 7일 실행이 0.6441달러(약 900원),
고친 뒤 9월 6일치를 다시 만든 실행이 **0.4209달러(약 590원)** 였습니다. 35% 줄었습니다.

고치기 전 청구서를 뜯어 보니 **모델이 써낸 글이 72%**, 캐시 웃돈이 20%, 모델에 들어간 글이
8%였습니다. 그래서 여섯 가지를 고쳤습니다 — 영상 대본과 브리핑을 값싼 모델로, 한 번도 읽히지
않던 캐시를 걷어내고, 유튜브 설명란·고정 댓글은 프로그램이 만들고, 후보 개수와 B롤 지시를
줄이고, 근거 기사를 긴 주소 대신 번호로 주고받게 했습니다.

| | 하루 | 한 달 |
| --- | --- | --- |
| 실측 (고치기 전) | 약 900원 | 약 2만 7천 원 |
| **실측 (여섯 가지 고친 뒤)** | **약 590원** | **약 1만 8천 원** |
| 아껴 쓰기 설정 | 약 230원 | 약 7천 원 |

고친 뒤 실행의 세 번을 나눠 보면 브리핑 0.107달러(sonnet), 블로그 0.152달러(opus),
영상 대본 0.162달러(sonnet)입니다. 가장 비싼 것은 여전히 블로그 글이고, 그건 유일하게
opus 를 쓰는 자리입니다 — 사람이 그대로 올리는 글이라 그렇게 두었습니다.

(1달러 1,400원 기준입니다. 환율에 따라 달라집니다.)

**한산한 날은 글을 만들지 않습니다.** 정치 뉴스가 없는 날에도 억지로 다섯 꼭지를 채우면
한 매체만 다룬 잔뉴스로 글이 찹니다. 매일 같은 틀로 쓰는 글이라 그런 날이 쌓이면 검색에서
불리해집니다. 큰 사건이면 반드시 여러 매체가 받아쓰므로, **여러 곳이 함께 다룬 이야기가
하나도 없는 날**은 "오늘은 쉬어 가는 날"이라고 알림만 보내고 넘어갑니다. 통계는 그대로 모으고,
직접 만들고 싶으면 그날 폴더의 `prompt-pack.md`를 쓰면 됩니다.

**결과가 나빠졌는지 숫자로 봅니다.** 발행 전 점검표와 숫자 검산 결과를 날마다 쌓아
운영 현황 화면에 표로 보여 줍니다. 값싼 AI 모델로 바꾼 날 무엇이 달라졌는지 하루 만에 보입니다.

**글이 언제 기준인지 밝힙니다.** 검색으로 반년 뒤에 들어온 사람은 그때 숫자를 지금 값으로
읽습니다. 글 맨 위에 "이 글은 9월 8일 기준입니다" 한 줄이
들어가고, 사이트에서 한 달 지난 글에는 안내 띠가 붙습니다.

**유난히 비싼 날은 알려 줍니다.** 그날 비용이 평소의 두 배를 넘으면 아침 알림에 경고가 붙습니다.
한 달 예산 경보는 한 달이 다 지나야 울리는데, 그 사이 프롬프트가 길어지면 조용히 몇 배가 나갈 수 있어서입니다.
알림에는 그날 비용도 원화로 함께 옵니다.

아껴 쓰려면 `config/settings.yaml` 파일에서 이 부분을 고칩니다.

```yaml
llm:
  model: claude-sonnet-5     # 원래는 claude-opus-5
```

깃허브 화면에서 파일을 누르고 연필 아이콘을 눌러 고친 뒤 **Commit changes** 를 누르면 됩니다.

## 내 채널에 맞게 바꾸기

글과 대본의 말투를 정하는 곳은 `config/settings.yaml` 파일입니다.
아래 부분만 사장님 채널에 맞게 고치면 결과가 확 달라집니다.

```yaml
video:
  channel_name: "방구석 배경지식"          # 채널 이름
  audience: "내 집 마련을 준비 중인 30~50대"   # 누구에게 말하는지
  tone: "차분하고 단정한 정보 전달"          # 어떤 말투로
  shorts_seconds: 60                    # 쇼츠 길이(초)
  longform_minutes: 8                   # 롱폼 길이(분)
  speaking_rate_cpm: 330                # 1분에 몇 글자 말하는지
  banned_phrases:                       # 절대 쓰면 안 되는 말
    - "무조건 오른다"
    - "지금 안 사면 늦는다"
```

- **`audience`, `tone`** 은 자세히 쓸수록 결과가 좋아집니다.
- **`speaking_rate_cpm`** 은 사장님 말 속도입니다. 대본이 자꾸 길거나 짧으면 이 숫자를 조절하세요.
  말이 빠르시면 380, 느리시면 280 정도로요.

다루는 주제를 바꾸려면 `config/sources.yaml` 의 `keywords` 에서 숫자(`weight`)를 조절합니다.
숫자가 큰 주제가 먼저 뽑힙니다. 재건축 위주 채널이라면 `공급·정비사업` 의 숫자를 3.5로 올리세요.

## 문제가 생기면

**아침에 글이 안 만들어졌어요**

**Actions** 탭에 들어가 보세요. 빨간 X 표시가 있으면 눌러서 무슨 일이 있었는지 볼 수 있습니다.
가장 흔한 원인은 1~3단계 설정이 빠진 것입니다.

**뉴스를 하나도 못 가져와요**

**Actions** → **피드 점검** → **Run workflow** 를 눌러 보세요.
❌ 표시가 난 뉴스 사이트는 주소가 바뀐 것입니다. `config/sources.yaml` 에서
그 항목의 `enabled: true` 를 `enabled: false` 로 바꾸면 건너뜁니다.

2026년 9월 6일 점검 기준으로 **10개 소스가 정상**이고 하루 **300건 이상** 모입니다.
(이데일리·서울경제는 주소가 막혀서 꺼 두었습니다.)

**글은 나오는데 요약이 없어요**

AI 열쇠(1~2단계)가 없거나 잘못된 것입니다. 이럴 땐 `prompt-pack.md` 라는 파일이 대신 생깁니다.
그걸 통째로 복사해서 챗봇에 붙여넣으면 같은 결과를 얻을 수 있습니다.

**주소 앞에 '주의 요함' 이라고 뜹니다 (자물쇠가 없어요)**

개인 도메인에 자물쇠(HTTPS)가 아직 안 걸린 상태입니다.
**Settings** → **Pages** → 아래쪽 **Enforce HTTPS** 에 체크하세요.
체크가 회색으로 눌리지 않으면 인증서를 만드는 중이니 몇 시간 뒤 다시 보세요.

자물쇠가 걸려야 브라우저가 경고를 띄우지 않고, 복사 버튼도 모든 브라우저에서
안정적으로 동작합니다.

**내용이 이상하거나 숫자가 틀린 것 같아요**

**꼭 확인하세요.** AI가 기사를 잘못 읽을 수 있습니다.
**제작 메모** 문서의 4번 항목에 "확인이 필요한 것" 이 정리돼 있습니다.
숫자를 방송이나 블로그에 올리기 전에 **기사 원문** 과 대조하는 습관을 권합니다.
